# Notes for AI coding agents

Melbourne Traffic Lab is a static TypeScript site with no backend (npm workspaces):

- `simulation/` — the NetLogo traffic model, its data and build tools, and the TypeScript that runs it in a browser Web Worker (NetLogo Web) or in Node.
- `frontend/` — the React + Vite page, organised by feature under `src/features`. A Vite plugin (`frontend/vite/simulationFiles.ts`) serves and copies `simulation/runtime` to `/sim`.
- `e2e/` — Playwright tests of the built site.
- `vercel.json` — Vercel builds with `npm run build` and serves `frontend/dist` with the security headers.

Read `README.md` first, then `simulation/README.md` and `docs/design.md`.

## House style

- TypeScript everywhere (strict mode).
- Use `if` / `else`, never the `? :` operator.
- Use `function () {}`, never arrow functions.
- Every file starts with a short comment saying what it is for; explain non-obvious functions.
- Write labels and messages on the page in plain, everyday Australian English.
- `npm run lint` enforces the `? :` and arrow rules; `npm run format` handles layout.

## Checks before finishing

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run format:check
```

## Things to know

- `simulation/src/createTrafficSim.ts` is the only interface to the model. Add new model access there and whitelist it; never let the page send raw NetLogo code.
- Settings (names, defaults, limits) live once, in `simulation/src/settings.ts`. The page only adds labels in `frontend/src/features/settings/labels.ts`.
- Reads from the model go through `read()` in createTrafficSim, which uses a cloned random generator so watching the model never changes its results.
- Security headers live in `frontend/vite/securityHeaders.ts` and must match `vercel.json`; a test checks this.
- `simulation/runtime/model.js`, `reporters.js` and `network-*.json` are generated by `npm run model:web`; `worker.js` and `batch-worker.js` are built by `npm run build`. Do not edit them by hand.
- The works planner (`frontend/src/features/planner/`) runs scenarios through `simulation/src/scenario.ts` in batch workers and remembers results in the browser (`resultCache.ts`). When the model's behaviour changes, bump the version in that file's `STORAGE_KEY` so old results are not reused.
- The Report page is chosen by the address's `#report` part (`frontend/src/app/useView.ts`), so the site stays one static page and needs no server rewrites. Other in-page links (`#workbench`, `#compare`) show the simulator.
- The Python tools in `simulation/netlogo/tools/` reproduce the committed model and map byte for byte. Keep it that way when changing them.
