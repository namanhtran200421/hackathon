# Notes for AI coding agents

Melbourne Traffic Lab is a TypeScript monorepo (npm workspaces):

- `packages/simulation` — the NetLogo traffic model, its data and build tools, and the TypeScript that runs it in a browser Web Worker (NetLogo Web) or in Node.
- `apps/server` — Express server: security headers, compression, `/api`, `/sim` and the built page. No database.
- `apps/web` — React + Vite page, organised by feature under `src/features`.
- `e2e` — Playwright tests of the whole site.

Read `README.md` first, then `packages/simulation/README.md` and `docs/design.md`.

## House style

- TypeScript everywhere (strict mode).
- Use `if` / `else`, never the `? :` operator.
- Use `function () {}`, never arrow functions.
- Every file starts with a short comment saying what it is for; explain non-obvious functions.
- Write labels and messages on the page in plain, everyday Australian English.
- `npm run lint` enforces the `? :` and arrow rules; `npm run format` handles layout.

## Checks before finishing

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run format:check
```

## Things to know

- `packages/simulation/src/createTrafficSim.ts` is the only interface to the model. Add new model access there and whitelist it; never let the page send raw NetLogo code.
- Settings (names, defaults, limits) live once, in `packages/simulation/src/settings.ts`. The web page only adds labels in `apps/web/src/features/settings/labels.ts`.
- Reads from the model go through `read()` in createTrafficSim, which uses a cloned random generator so watching the model never changes its results.
- `packages/simulation/runtime/model.js`, `reporters.js` and `network-*.json` are generated by `npm run model:web`; `worker.js` is built by `npm run build`. Do not edit them by hand.
- The Python tools in `packages/simulation/netlogo/tools/` reproduce the committed model and map byte for byte. Keep it that way when changing them.
